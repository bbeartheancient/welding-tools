Key design of the plan (token conservation per turn):
Principles:
1. Persist everything durable to small files on disk: PLAN.md (the plan + a checklist with status), FACTS.md (the extracted game facts). Each execution turn: read PLAN.md (~1.5-2k tokens) → identify the next unchecked step → do the minimum reads needed (grep / windowed reads of the deobf files) → write the output → check off the step in PLAN.md. Compaction-safe.
2. The raw and deobfuscated JS (180KB ≈ 50k+ tokens each if fully read) is only read in a targeted way during the fact-extraction step, and never again after FACTS.md is complete. All build steps read only FACTS.md + the module file currently being built.
3. No dependencies: vanilla JS + canvas/SVG in the browser; node built-ins only for the tooling. No npm install, no node_modules.
4. Each step = one bounded deliverable + a cheap verification gate; a step can be completed in a single short session.
5. Steps are strictly ordered with explicit "done when" gates; a step can't be started until the previous step's gate passes.
